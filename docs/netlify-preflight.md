# Netlify — מה להגדיר לפני הפריסה הראשונה

המסמך הזה נכתב כדי שהפריסה הראשונה תהיה רצף פעולות ולא חקירה. הוא מניח שהאתר
עדיין לא עלה לאוויר, וש-Netlify הוא היעד.

---

## 1. משתני סביבה

הרשימה הזו היא כל משתנה שהקוד קורא בפועל — לא רשימת משאלות.

### ציבורי · נדרש עכשיו

נכללים ב-bundle של הדפדפן. זה בסדר: אף אחד מהם אינו סוד.

| משתנה | ערך | למה נדרש |
|---|---|---|
| `NEXT_PUBLIC_SANITY_PROJECT_ID` | מלוח הבקרה של Sanity | **הבנייה נכשלת בלעדיו.** כל התוכן נקרא בזמן build |
| `NEXT_PUBLIC_SANITY_DATASET` | `production` | ברירת מחדל קיימת, אך עדיף מפורש |
| `NEXT_PUBLIC_SANITY_API_VERSION` | `2026-09-07` | נעוץ בכוונה; שינוי משנה התנהגות שאילתות |
| `NEXT_PUBLIC_SUPABASE_URL` | `https://<ref>.supabase.co` | התחברות ומועדפים |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `sb_publishable_…` | מוגן ב-RLS; לא מעניק דבר לבדו |
| `NEXT_PUBLIC_SITE_URL` | `https://<דומיין>` — origin בלבד, בלי סלאש בסוף | **קריטי.** ממנו נבנים canonical, Open Graph, כל ה-sitemap, השורה ב-robots.txt וה-redirect של ההתחברות |

> ⚠️ **`NEXT_PUBLIC_SITE_URL` נצרב בזמן הבנייה.** שינוי שלו מחייב deploy מחדש —
> לא מספיק לשמור אותו בלוח הבקרה.

### צד-שרת בלבד · נדרש עכשיו

לעולם לא בקידומת `NEXT_PUBLIC_`. נקראים רק ממודולים המסומנים `server-only`.

| משתנה | ערך | למה |
|---|---|---|
| `RESEND_API_KEY` | `re_…` | טופס יצירת הקשר. בלעדיו העמוד מודיע שהשליחה כבויה ומסרב לקבל הודעה |
| `CONTACT_TO_EMAIL` | `rotemadini@gmail.com` | אופציונלי — זו כבר ברירת המחדל |

### נדרש בהמשך · Grow

**אין להגדיר עכשיו.** אף אחד מהם אינו נקרא בקוד פעיל היום.

| משתנה | מתי |
|---|---|
| `SUPABASE_SECRET_KEY` | כשנפתחת הסליקה — הדרך היחידה לכתוב שורת רכישה/הרשאה |
| סודות Grow | כשמתחילים את אינטגרציית Grow |
| `CONTACT_FROM_EMAIL` | כשדומיין מאומת ב-Resend (ראו §5) |

### לא נדרש ב-Netlify כלל

| משתנה | למה לא |
|---|---|
| `SANITY_API_WRITE_TOKEN` | כלי מיגרציה משורת הפקודה בלבד. **אין להוסיף אותו ל-Netlify** — הוא מעניק הרשאת כתיבה לכל התוכן |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | נתמך רק כגיבוי לשם הישן של המפתח |

**נבדק:** סריקה של ה-bundle שנבנה מצאה **אפס** אזכורים ל-`RESEND_API_KEY`,
`SUPABASE_SECRET_KEY`, `SANITY_API_WRITE_TOKEN`, `CONTACT_TO_EMAIL` או
`api.resend.com` תחת `.next/static`.

**מה קורה אם שוכחים משתנה:** חסר `NEXT_PUBLIC_SANITY_PROJECT_ID` — הבנייה
נכשלת עם הודעה מפורשת (`requireProjectId()`). חסרים משתני Supabase — האתר
נבנה ועובד, וההתחברות נשארת רדומה. חסר `RESEND_API_KEY` — האתר נבנה, וטופס
יצירת הקשר אומר שהוא כבוי.

## 2. הגדרות בנייה

מגיעות מ-[`netlify.toml`](../netlify.toml), אין צורך להקליד אותן:

- פקודת בנייה: `npm run build`
- תיקיית פרסום: `.next` (Next Runtime של Netlify מנתב אותה בעצמו)
- `NODE_VERSION = "22"` — Next 16 דורש Node ≥ 20.9, וגרסת ברירת המחדל של
  תמונת הבנייה ב-Netlify משתנה עם הזמן. הנעילה מונעת בנייה שנשברת מעצמה

`netlify.toml` **אינו** מגדיר הפניות או כותרות בכוונה: כולן נוצרות ב-
`next.config.ts`, ועותק שני היה מתיישן.

**נקודת אי-ודאות אחת:** התאימות של Next 16 ל-Next Runtime של Netlify לא נבדקה
כאן ואי אפשר לבדוק אותה בלי פריסה. זו בדיוק המטרה של התצוגה המקדימה הראשונה.
אם היא נכשלת, הסימן יהיה שגיאה בשלב ה-Runtime ולא בשלב ה-build.

## 3. מה לבדוק בתצוגה המקדימה הראשונה

| בדיקה | מה אמור לקרות |
|---|---|
| `/` | 200 |
| מתכון כלשהו | 200 |
| `/recipes/not-a-recipe` | **404 אמיתי** (לא 200) |
| `/dates/01` | **308** אל הכתובת העברית |
| `/sitemap.xml` | 186 כתובות, כולן על הדומיין האמיתי |
| `/robots.txt` | שורת `Sitemap:` על הדומיין האמיתי |
| `/contact` | הטופס נטען; אם `RESEND_API_KEY` מוגדר — בלי הודעת ״לא פעיל״ |
| `/gifts` | 404 (מוסתר בדגל) |
| כפתור הנגישות | מופיע, נפתח, וההעדפה נשמרת אחרי רענון |

## 4. אחרי חיבור הדומיין

לפי הסדר:

1. הצמידו את הדומיין ב-Netlify והמתינו לתעודת HTTPS.
2. עדכנו את `NEXT_PUBLIC_SITE_URL` ל-`https://<דומיין>` ו**הריצו deploy מחדש**.
3. **Supabase** → Authentication → URL Configuration: `Site URL` = הדומיין;
   הוסיפו `https://<דומיין>/auth/callback` ל-Redirect URLs.
4. **Google Cloud Console** → OAuth client: הוסיפו את כתובת ה-callback של
   Supabase ל-Authorized redirect URIs.
5. **Sanity** → API → CORS Origins: הוסיפו `https://<דומיין>`. אין צורך
   ב-credentials — הקריאות ציבוריות ומתבצעות בזמן build.
6. הפעילו Force HTTPS ב-Netlify.
7. אחרי כמה ימים יציבים: בטלו את ההערה של בלוק ה-HSTS ב-`netlify.toml`,
   מתחילים ב-`max-age=300` ומעלים ל-`31536000` רק אחרי ששום דבר לא נשבר.
8. הגישו את ה-sitemap ב-Google Search Console.

## 5. הפעלת טופס יצירת הקשר (Resend)

הטופס בנוי, נבדק ועובד. חסר לו רק מפתח. **אין צורך לשנות קוד.**

1. **פתחו חשבון** ב-[resend.com](https://resend.com). המסלול החינמי נותן
   3,000 הודעות בחודש (עד 100 ביום) — הרבה מעבר לצורך.
2. **צרו API key**: Dashboard → API Keys → Create. הרשאת **Sending access**
   בלבד; הוא לא צריך לקרוא דבר. העתיקו אותו מיד — הוא מוצג פעם אחת.
3. **הוסיפו ב-Netlify** (Site configuration → Environment variables):
   - `RESEND_API_KEY` = המפתח
   - `CONTACT_TO_EMAIL` = `rotemadini@gmail.com` *(אופציונלי — זו ברירת המחדל)*
   הריצו deploy מחדש.
4. **בדיקה בטוחה:** פתחו `/contact` באתר החי ושלחו הודעה לעצמכם. שלוש בדיקות:
   - ההודעה מגיעה ל-Gmail תוך שניות;
   - לחיצה על ״השב״ פונה לכתובת שהוזנה בטופס, לא לכתובת השולח;
   - שליחה עם שדות ריקים מציגה סיכום שגיאות אדום ולא שולחת דבר.
   אם משהו לא עובד, העמוד **לעולם לא יאמר שההודעה נשלחה** — הוא יגיד במפורש
   שהיא לא נשלחה.
5. **כשהדומיין מאומת:** עד אז השולח הוא `onboarding@resend.dev`, וזה עובד.
   אחרי אימות הדומיין ב-Resend (Domains → Add Domain, והוספת רשומות ה-DNS
   שהוא נותן), הוסיפו:
   `CONTACT_FROM_EMAIL` = `רותם עדיני <noreply@<דומיין>>`
   ההודעות יגיעו מכתובת של הדומיין ויעברו טוב יותר מסנני זבל. כתובת הפונה
   תמיד נשארת ב-Reply-To ולעולם לא ב-From.
6. **לעדכן את מדיניות הפרטיות:** סעיף 3 כתוב היום בלשון עתיד ופותח במשפט
   שהשליחה אינה פעילה. עם ההפעלה יש להעביר אותו ללשון הווה, להסיר את הסימון
   ״מתוכנן״ מ-Resend בסעיף 10, ולמלא את סעיף 13 אחרי בדיקת מדיניות השמירה
   בחשבון Resend.
