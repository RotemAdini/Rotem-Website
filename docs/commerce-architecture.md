# ארכיטקטורת מסחר והרשאות — רותם עדיני

## עקרונות

- לכל משחק יש מזהה קבוע שאינו משתנה כאשר משנים כותרת, מחיר או תמונה.
- חבילה היא מוצר שמכיל רשימת משחקים הניתנת לשינוי עבור רכישות עתידיות.
- תשלום מאושר יוצר רשומת רכישה ורשומות זכאות נפרדות לכל משחק שניתן בעסקה.
- שינוי מבצע או חבילה אינו מוחק זכאות קיימת.
- הענקה ידנית לפי אימייל יוצרת זכאות מתועדת עם סיבה ומי שהעניק אותה.

## ישויות עתידיות ב-Supabase

| ישות | תפקיד |
| --- | --- |
| `profiles` | פרטי החשבון המחובר |
| `games` | קטלוג משחקים ומצב פרסום |
| `products` | משחק יחיד או חבילה, עם מחיר בסיס |
| `product_items` | המשחקים הכלולים בכל מוצר חבילה |
| `promotions` | מבצעים, תוקף וקודי קופון |
| `purchases` | תוצאת תשלום מאומתת מ-Grow |
| `entitlements` | זכות הגישה בפועל למשחק |
| `manual_grants` | הענקה ידנית, סיבה ותיעוד |

## זרימת רכישה

1. המשתמשת רואה קטלוג פתוח ומשחקים נעולים/פתוחים לפי חשבונה.
2. בלחיצה על רכישה היא מתחברת ב-Google או באמצעות קוד למייל.
3. השרת מחשב את המחיר והמבצע התקפים, ולא סומך על מחיר מהדפדפן.
4. Grow מעבדת את התשלום ושולחת אישור ל-webhook מאובטח.
5. השרת מאמת את האירוע פעם אחת בלבד, יוצר `purchase` ו-`entitlements`.
6. המשתמשת חוזרת לאתר ורואה את המשחק פתוח מיידית.

## כלל חבילות

המשחקים שניתנו בעסקה נשמרים בזכאויות בזמן הרכישה. אפשר לשנות מה ייכלל בחבילה עבור קונים עתידיים, ולהציע לקונים קודמים מחיר שדרוג או גישה נוספת — בלי למחוק גישה קיימת.
